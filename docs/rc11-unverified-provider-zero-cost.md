# RC11 — Unverified provider cost is not a free-compute grant

Cloud/provider-backed model deployments and third-party Agent Runtime connections cannot obtain a zero-cost routing exemption merely by placing `"cost_class":"free"`, `"cost_class":"local"` or `"hard_zero_incremental_cost":true` in connection metadata. For provider-backed models, those claims are classified as `unknown` with `hard_zero_incremental_cost=false`; legitimate explicitly classified `paid`, `provider_managed` and `included_subscription` remain subject to their existing approval restrictions. The catalogue will not schedule a provider claiming free on a no-spend route.

The inference executor independently requires a bound budget reservation for **any** provider-associated deployment, including one claiming free. That is defence-in-depth against callers that bypass routing or submit stale selections. This is a conservative fail-closed change: free-tier provider requests require explicit monetary-spend consent and reservation until OnePane has an independently validated, enforceable zero-charge provider contract mechanism. It does not charge money itself, nor imply a provider does in fact charge a fee. True provider-less local models continue to require no external provider budget.

This affects older OmniRoute/free-provider catalogue entries that relied on self-described no-fee metadata. An opt-in provider flow is still available using proper Task, information-flow and budget authority; local-first/autonomous $0 modes never silently substitute them. Hosted tests do not establish actual provider billing or network safety on installed hardware.
