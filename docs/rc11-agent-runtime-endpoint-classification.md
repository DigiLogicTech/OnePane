# RC11: Agent Runtime routing versus actual destination trust

A third-party Agent Runtime / Hermes bridge is **not** a verified model deployment. Its `capabilities_json.scheduling` is self-reported, and a bridge on localhost may itself call commercial cloud LLMs or forward data. Therefore, an Agent Runtime can **never** acquire a hard-zero-cost/local-compute claim from its JSON cost flag alone.

- The Scheduler lists such runtimes at `cost_class=unknown` and `hard_zero_incremental_cost=false` unless already declared paid or provider-managed, which are both conservatively chargeable. A claimed included subscription is treated as **unknown monetary cost**, not an authenticated entitlement, because the subscription-only opt-in is not approval for arbitrary monetary spend. `LocalOnly`, `RequireZeroIncrementalCost`, and default no-spend routing do not silently admit them.
- An `origin_node` policy is accepted only for the built-in `builtin.agent_protocol_http@1` bridge, linked to a canonical local-trust Node record and an endpoint URL with a **literal loopback IP**. HTTPS or HTTP is allowed; DNS names including `localhost`, RFC1918/private nonloopback addresses, userinfo URLs, invalid ports, queries and fragments are **not proof**. The final Agent Runtime invocation boundary independently revalidates the same URL before selecting the transport.
- A policy naming `trusted_node` is **not** proof of live paired Node transfer approval; such runtimes remain unschedulable, and invocation's existing unimplemented trusted-node transport blocks use. Unknown remote or provider destinations remain cloud (explicit untrusted remains untrusted), not elevated by metadata.
- A verified local **transport address** is not evidence the external harness runs its inference locally, has no internet access, or avoids spend. Full per-Task cross-Workspace/network/data-flow consent, transport peer authentication, DNS/redirect/rebinding hardening for other protocols, and physical installed Node acceptance remain release gates.

This source change makes previously permissive unsupported runtime variants explicitly ineligible for autonomous scheduling. Legitimate host-loopback bridges can remain a selectable, **potentially chargeable** Agent Runtime under the existing policy gates. Direct human-mediated runtimes and managed ModelDeployment local-first scheduling remain distinct paths.

The final integrated code/security audit and LAST human-first UI/UX alignment still precede a user-approved Windows/Ubuntu QA installer. No physical probe or release merge is authorised.

The built-in HTTP bridge is a second independent enforcement point: even when called directly, it refuses an `origin_node` label with anything other than a literal loopback-IP endpoint. Plain HTTP bearer authentication no longer treats the DNS name `localhost` as sufficient secrecy evidence; use explicit `127.0.0.1` or `[::1]` instead. These are transport-address checks and cannot prove the bridge's own upstream calls are local or free. Runtime connection revocation, endpoint/adapter/secret/mode changes and policy drift are also re-read after authorization and immediately before dispatch; changed identities block execution and release an unspent reservation.

**Taskless Assistant restriction:** An invocation with no canonical Task has no Project/Workspace/Agent execution grants. The only Agent Runtime allowed through this source-level admission is the exact built-in proposal-only HTTP bridge on an explicitly enrolled local Node with a literal loopback-IP endpoint, no attached credential, and a policy declaring `origin_node`. Other Taskless external/paired, gateway-mediated, credential-bearing or cloud-labelled runtimes fail before invocation or transport. Even this narrowly allowed local HTTP bridge still requires the ordinary explicit budget reservation; its *compute* is not independently attested. For remote Agent Runtime usage, create a scoped Task with positive network/data-flow/budget approval. A local bridge can still make its own upstream calls: sandbox-level network egress control remains an independent later gate.

A runtime's unverified `included_subscription` label cannot bypass `AllowPotentialMonetarySpend`: unlike a first-party verified provider entitlement, third-party metadata does not establish allowance, billing identity, upstream provider or hard spending limits. Regression covers local/free/included/paid/provider-managed claims and proves subscription-only consent cannot route an unknown-cost Agent Runtime.

## Host-origin custom dialer hardening (2026-10-15)

The built-in Agent Protocol HTTP bridge now constructs a new direct `http.Transport` for origin-only invocations. An arbitrary caller-provided `*http.Transport` is **not** cloned into that security boundary: clearing its proxy does not neutralise custom `DialContext`, `DialTLSContext`, `TLSNextProto`, or other transport hooks that could forward private content to an off-host receiver. Opaque `RoundTripper` implementations remain denied. Local HTTPS uses the host's normal trusted certificate authorities instead of caller-injected TLS behavior. The regression uses a local interception sink to prove an injected dialer never receives the private request; it does **not** prove that the target Agent Runtime performs inference locally, or replace OS egress isolation or installed physical Node verification.

## Bounded execution of opaque Agent Runtime HTTP calls (2026-10-15)

An omitted `timeout_ms` previously inherited an unbounded `http.Client.Timeout=0` (or a caller-provided timeout longer than the configured maximum), which could occupy scarce Workers and leave a metered invocation in unknown progress indefinitely if the bridge stopped responding. The HTTP adapter now always gives a request a finite client deadline: an explicit `timeout_ms` remains authoritative up to its existing 10-minute upper limit; otherwise an existing positive shorter client deadline is retained and absent, negative, or longer-than-ten-minute caller timeouts are clamped to ten minutes. The original request `context.Context` may still cancel earlier. A timeout after dispatch remains an **unknown external outcome**; OnePane must not automatically replay billable external effects or claim provider cancellation. This is one bounded adapter call, not a time limit on overall multi-step Project completion. The Worker can checkpoint/resume subsequent authorised work.

## Final-boundary malformed policy denial (2026-10-15)

The built-in Agent Protocol HTTP adapter now denies an explicitly supplied but malformed `data_policy_json` **before constructing or sending any HTTP request**. Previously it discarded a JSON unmarshal error and could treat a malformed `origin_node` declaration as an unrestricted remote label when a caller reached the adapter directly outside Service admission. Existing Service-level policy validation remains required; this change is independent defence in depth. Regression uses a loopback interception fixture that must receive zero requests for truncated, wrong-typed and non-object policies. An omitted raw policy in older direct adapter unit tests retains its existing legacy behaviour, but cannot independently confer canonical origin trust, remote network consent or scheduling permission.
