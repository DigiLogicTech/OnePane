# RC11 P0-AE — Offline historical three-key execution review

The legacy onepane-node-custody verify subcommand only verifies the original instrument and Node software-key custody signatures; it does not establish human Node-execution approval. The new verify-execution subcommand requires the original private witness, instrument report, OnePane challenge, exact approved private probe plan, separately operator-signed human execution permit, original independently pinned Node PEM certificate/fingerprint, instrument public key, and human operator public key.

Its verification first checks the signed instrument report and original human OnePane challenge/plan against the paired Node custody signature, then verifies the independent human Ed25519 operator signature over the original exact challenge-scoped Node permit. It checks permit Node ID, enrolled fingerprint, source, declared target/TLS pin, Project/Goal, instrument public key and receipt observation/witness chronology as-of historical signed witness time. A past success does not authorise a new probe. The human public key must be distinct from Node and instrument identities. A changed or replaced permit file fails signature verification.

All three software keys authenticate only cryptographic custody and deliberately declared approval data. The operator key is not yet registered against a OnePane Workspace principal using an independently signed server enrollment certificate, and the permit itself is NOT signed by OnePane. The human must obtain permit and original approvals through an independently authenticated API session and protect the transfer. The Node is still not hardware attested, and a TCP connect does not establish physical target identity or independent true sensor data. No monitoring, incident vote or L5 remediation permission arises from successful offline verification.

CI tests use only mock TCP dialers and synthetic certificates: original three-key chain success, incorrect operator, reuse of instrument as human, altered grant/challenge/signature and unrelated Node. Physical Node and installed Windows/Ubuntu trust are separate release gates.
