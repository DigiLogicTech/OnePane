# Managed Local AI install pipeline

OnePane owns the complete local-model lifecycle; users do not need to preinstall Ollama, llama.cpp, or LLMFIT.

## Trust and catalog

Release/runtime/model artifact metadata is supplied by a signed local-AI catalog. The envelope is Ed25519 signed and OnePane pins accepted public keys in bootstrap configuration. The exact signed catalog revision is bound to each install job, so an update cannot change artifacts after approval.

Catalogs may also carry model-fit metadata. When present, recommendations and downloadable artifacts therefore come from the same signed update domain. The small compiled-in model list is only an offline advisory fallback and is not sufficient to authorize a one-click download.

A downloadable runtime or model must have a trusted SHA-256 digest. Runtime downloads are HTTPS-only; model files are content-addressed by their digest and runtime releases live in versioned directories.

## Durable one-click flow

A user-selected recommendation becomes a trusted-code-generated install plan and an explicit human approval. The daemon then owns a durable install job:

`QUEUED -> RESOLVING -> PROVISIONING -> STARTING -> QUALIFYING -> READY`

The job is crash-recoverable. In-flight jobs become `INTERRUPTED` after daemon restart and reconcile durable plan/deployment state before resuming. They do not blindly re-register models or deployments.

A model does not enter scheduler-ready state simply because its files were downloaded. The managed llama.cpp server must start successfully and empirical qualification must exercise protocol behavior and context before the deployment becomes READY.

## Residency

Qualified local deployments are lazy-loadable. The normal inference transport starts a stopped managed runtime on demand, checks process identity and loopback health, and updates last-use state. An idle reaper may stop healthy runtimes after `local_ai.idle_unload_minutes` to release VRAM/RAM; the next routed inference starts them again.

## Current release-signing requirement

The backend supports configured Ed25519 catalog trust roots now. A production OnePane release still needs the actual OnePane release public key and signed catalog artifact to be generated by the release pipeline before the installer can offer curated one-click models out of the box.
