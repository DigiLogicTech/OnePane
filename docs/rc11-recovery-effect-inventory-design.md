# Interrupted Task recovery effect inventory design

Status: design dependency reviewed against source on 24 October 2026. The general effect inventory, authenticated human disposition and independent postcondition verification are **not implemented**. Intake/discovery and scoped metadata inspection do not resolve recovery cases. This document records the ownership investigation so continuation does not repeat it.

Implemented dependency checkpoint: private `internal/recoveryinventory` now validates the direct Task/Attempt structural slice (40 classified tables); migrations0104–0106 add30missing direct/reverse/nested provenance lookup indexes with populated upgrade and actual planner tests. This is not a complete semantic ownership contract or collector. The later design sections retain the full requirements; their earlier statement that these prerequisites are unimplemented is superseded only for this explicit slice. No case phase, recovery authority or execution admission changes.

The standalone `ClassifyModelRequestAttribution` dependency now classifies exact stored two-message model envelopes with a complete protocol-v1 ordinary Worker Task/Attempt identity. It bounds stored UTF-8 bytes (64KiB), nested depth (32), shared outer/inner tokens (8192), object entries (2048) and identity bytes (512), rejects duplicate decoded keys/case aliases, malformed or unsupported encodings and missing lineage, and hashes bounded original bytes with a versioned domain. Unknown results retain no partial identities. It accepts no database scope and does not authenticate the producer, validate optional provider-generation settings, clear unmatched/unsupported requests or authorize recovery. No database attribution ledger, write-time enforcement, complete reverse semantic contract or collector invokes it yet. Those remain prerequisites to bounded complete attribution: a NULL expression-index key must never establish absence of effects.

## Trust and implementation boundary

A private immutable database observation is the next dependency. It is not actual process termination, a file-content probe, a human decision, verification of an external effect, permission to retry, or completed cancellation. Preserve the original interrupted Attempt/Worker, all admission fences and the case's truthful `awaiting_inventory` phase. Do not add a public effect-payload API or invoke adapters while collecting an inventory.

The existence lists in `internal/task/cancel_settlement.go` and `internal/team/cancellation_evidence.go` are conservative pristine-cancellation guards, not a complete general inventory specification. A count or digest of those existence results cannot stand in for complete effect history.

An eligible constrained first implementation may observe an ordinary Task interrupted between `Task.Start` and Worker creation, with bounded exact-scope descendants and historical Attempts, but **zero other dispatch/effect/Worker/Team/context associations**. It must reject unsupported associations, including foreign rows that reference an owned Attempt. Its evidence label must explicitly mean an empty-effect **database observation for that constrained history**, never general recovery completion. All historical Attempts and the entire bounded relevant audit must still be materialized rather than represented by counts. Any later expansion requires its own ownership descriptors and negative acceptance matrix.

### Additional ownership paths confirmed during the 24 October review

These are required descriptor entries, not implemented collection or a declaration that the map is exhaustive:

- `tasks.plan_id` names a `plans` row, which names its `intent_revision_id` and may name a `supersedes_plan_id`. A constrained ordinary root must reject a non-null plan reference until that context has a reviewed descriptor. Similarly, `task_attempts.recovery_snapshot_id` is an outgoing reference in addition to the snapshot table's reverse Task/Attempt fields; disagreement cannot be hidden by querying snapshots only by Task.
- `agent_runtime_invocations.request_json` persists the full `agentprotocol.Request`, including top-level `task_id` and `attempt_id`, independently of the nullable columns. See `internal/agentruntime/invoke.go` and `internal/agentprotocol/types.go`. Both reverse JSON paths must be checked even when the column paths are absent or foreign. Team context-manifest paths are additional paths, not substitutes.
- Ordinary model dispatch also serializes the full AgentRequest, including original Attempt identity. `internal/agentworker/codec.go:buildModelRequest` stores it as a JSON **string** in `inference_requests.request_json` at `messages[1].content`; its surrounding message has role `user`. The nested AgentRequest is not a top-level JSON object field of the inference row. Review the known encoding and exact nested Task/Attempt fields, and reject malformed/unsupported encodings where they prevent attribution. Do not search arbitrary prompt text for an identifier or treat arbitrary mentions as ownership. The direct Task column alone does not establish complete original-Attempt coverage if independent persisted ownership fields disagree.
- `artifacts.metadata_json` has real reverse provenance paths. `internal/workspacepublisher/service.go` records `task_id` and `attempt_id` when creating a publication artifact. `internal/inference/execute.go` records `inference_request_id`; `internal/agentruntime/invoke.go` records `agent_runtime_invocation_id`; `internal/agentworker/execution.go` records `inference_request_id` and `agent_request_id` for the derived Agent response. Artifact creation commits before the caller can finish saving its request/publication association. Therefore a missing response-artifact column or publication row does not exclude an already-created artifact. Follow both the direct response reference and reverse metadata, preserving disagreement and orphan artifacts as evidence.
- `project_library_asset_versions.provenance_json` records `task_id`, `attempt_id` and `artifact_id` in `internal/projectworkspace/library_workspace_versions.go`. The exact `(asset_id,version)` may commit before a later caller publication association is saved. Reverse provenance must therefore be checked independently of `workspace_file_publications` and path mappings. A reused unchanged Library version preserves its original provenance; association with another Task must be read from that Task's exact publication record rather than rewriting provenance or assuming sole ownership of shared bytes.
- `assistant_turns.provenance_json.task_id` and `project_orchestrator_turns.provenance_json.task_id` duplicate their nullable Task columns (`internal/assistant/service.go`, `internal/projectorchestrator/service.go`). Reverse provenance cannot be silently omitted when the direct column is null or disagrees. The parent thread, handoff and orchestrator relations remain context, not authority to include every turn in the Project.
- Migration0001 also defines polymorphic `dependency_refs(owner_type,owner_id,target_type,target_ref,target_revision)`. Source review did not find a production writer establishing a closed Task/Attempt vocabulary. Explicitly classify these fields as unsupported polymorphic associations until their vocabulary is reviewed; schema presence cannot be dismissed merely because a current writer was not found. Existing owner and tenant/target indexes do not resolve the semantic question.
- `notification_deliveries` has both `source_event_id` and `source_event_seq`. Both can point back to a collected event and must agree when both are present; either association can reveal a delivery even without direct Task/Operation linkage. See migration0013. The existing `source_event_seq,target_id` index does not provide the equivalent `source_event_id` probe.

The same review confirmed that `global_resource_leases.owner_json.execution_id` is an available field in `resourcecoord.Owner`, but the current Operation acquisition callers populate Workspace and Task only. Do not invent an Attempt or Worker meaning for `execution_id`; a future typed descriptor must define that meaning before relying on it. Names such as `project_goal_tcp_reachability_alerts.attempt_id` reference **TCP probe Attempts**, not `task_attempts`; schema validation must classify FK targets rather than infer ownership solely from a suffix.

### Smallest honest implementation slices

**Still not implemented.** The immediate independent source deliverable can be a fixed ownership-descriptor/schema validator and bounded rejection probes, with integration tests against the fully migrated schema. It need not publish an inventory or change any case phase. Enumerate actual tables, columns, primary/composite keys and FK targets with SQLite schema introspection; explicitly classify direct ownership, typed references, reviewed JSON paths and shared context. Fail closed on an unclassified table/column/key change that affects the contract. Maintain reviewed exceptions for unrelated identically named identifiers. A schema digest or migration number alone is not the semantic coverage review.

After that contract passes, a deliberately narrower collector may support **one root Task with no parent, no descendants and exactly one historical Attempt: the original interrupted Attempt**. Read/materialize the complete bounded Task, Attempt, scoped ledger and related delivery/outbox records before evaluating this cardinality rule. A second historical Attempt must defer the case; it must not be removed with a WHERE filter. Retain the complete-history requirement when later widening this slice. Require the case's exact scoped unique interruption and immutable provenance. The root must have no result, plan, artifact session, named Workspace, execution profile, dependency edge in either direction or other context/effect association. A Project/tenant reference may be included as explicitly hashed context only after exact scope validation; it does not own all Project rows. Require a reviewed closed completion/Attempt-metadata shape; legacy `{"agent_worker":"v1"}` metadata is relevant to the historical orphan-start window, but arbitrary metadata cannot be silently ignored.

This narrow history is reachable in historical source: `agentworker.startRun` previously committed `Task.Start` before Worker creation. Current source commits Task/Attempt/Worker admission atomically, and `recoverOrphanedAgentAttempts` preserves historical orphan Attempts by interruption. Absence of a Worker is therefore an eligible database shape, not physical proof that nothing ran. Reject every unsupported row through **either** direct Task, original Attempt, incoming/outgoing typed reference or reviewed reverse JSON provenance, regardless of status or foreign/null scope columns. No Worker, Team/session/assignment/hold, Operation, tool/runtime/model dispatch, grant/resource/accounting/power record, snapshot/checkpoint/verification, publication/artifact/Library provenance, proposal or conversation context is allowed in this first slice. Every rejection descriptor requires an independent negative fixture with its alternate direct association absent or foreign. A deferred case remains unresolved.

Lifecycle delivery is an explicit exception to “no other associations”: Task creation enqueues `task.admission.evaluate`, interruption enqueues `task.recovery.required`, and capture appends its metadata audit. Materialize exact related jobs, claims, statuses and payloads instead of rejecting all outbox presence (which would make the normal positive path ineligible) or ignoring it. Reject unexpected job kinds/ownership, malformed payloads and related notification deliveries. Existing `task_recovery_cases` rows are intake context, not effect clearance. Observation IDs/audits added by the future collector must remain outside the effect fingerprint so duplicate observation does not invalidate itself.

Bounded execution remains a prerequisite. Migration0100 provides several direct Task indexes and migration0101 provides Team reverse dispatch indexes, but these do **not** cover the additional nested ordinary AgentRequest, runtime top-level JSON, artifact/Library/conversation provenance or polymorphic relationships above. Add reviewed indexes or another rigorously populated ownership representation before activating those probes. Assert actual `EXPLAIN QUERY PLAN` behavior with unrelated history present. `EXISTS`/`LIMIT 1` bounds returned rows, not work needed to establish absence; a whole-table JSON parse is not a bounded negative probe. Apply the existing byte caps before copying payloads, and bound total entries/bytes as well as each family. Until every supported reverse path is attributable with bounded work, leave the collector unwired and describe its output, if any, as a constrained private database observation, never complete general effect inventory or safe retry/cancellation evidence.

## Immutable observation and freshness protocol

1. Validate input bounds and the exact scoped original case lineage inside the transaction. Observe one clock value. Require complete interruption evidence using the same ownership principles as intake/discovery. Validate current Task scope and original interrupted Attempt rather than trusting captured metadata alone.
2. Discover the bounded graph with cycle deduplication and one whole-pass budget. Materialize all historical Attempts and each reviewed evidence family, closing readers before issuing more statements on the single-connection fixture. Reconcile duplicate paths by typed table/key identity; disagreement is an invalid observation, not a reason to pick one path.
3. Validate schema coverage. A fixed descriptor list must explicitly classify current ownership-bearing columns/tables and JSON ownership paths. New Task/Attempt/Operation ownership columns, renamed keys or changed required columns must fail closed until reviewed. Merely hashing `PRAGMA user_version` does not prove descriptor coverage. Do not invent a generic SQL identifier from request input.
4. Bound each collection with limit-plus-one and cap the **whole** snapshot's entries/bytes. Enforce byte limits before loading oversized JSON/payloads using `length(CAST(column AS BLOB))`; Go string/rune length or SQLite TEXT character length is insufficient. A full row count without bounded query/index work does not establish low-resource performance. Query-plan checks are required for new reverse probes.
5. Canonicalize typed records in fixed family/key order. Preserve null versus absent versus empty, integer precision, composite keys and array order. Include exact case/Task/Attempt/interruption identity, scope, format version, schema/descriptor identity, observed state/revisions/timestamps and digests of all relevant mutable payload fields. Some tables lack revisions; hashing IDs/counts/state alone misses changed effects.
6. Domain-separate the digest, for example a versioned OnePane recovery database-observation domain. Keep observation metadata/time separate from the effect fingerprint so unchanged observations can be compared; do not mix newly generated inventory IDs/audit events into the effect fingerprint. Append immutable observation and its audit atomically. Rollback must leave neither record on any failure. Duplicate capture can reuse the exact same case/version/fingerprint; it must not mutate an earlier observation.
7. Store private observation content only behind trusted internal ownership. Existing public recovery metadata omits raw reasons/prompts/effects; preserve that contract. No daemon/model/tool/API path should gain decision authority merely because an observation exists. Phase stays `awaiting_inventory` until the separately implemented full protocol defines otherwise.
8. Later human decisions bind exact inventory version/hash, expected case revision, authenticated human principal/credential and explicit requested disposition. Revalidate current credential/membership/capability and immutable human record inside the decision boundary. Do not accept model/self-issued proof.
9. Later independent verification binds the same original Attempt, precise resource/postcondition, actual immutable Observation IDs/versions, independent principal and freshness after the relevant effect/decision. Existing `operation.VerificationForOperation` checks Operation binding and levels/status via its caller; it does not establish recovery case hash or original-Attempt provenance and is not sufficient alone.
10. Recollect and compare the effect fingerprint transactionally before settlement; reject stale/changed/incomplete inventories. Preserve completed contributions, original interrupted histories and truthful unknown effects. Terminal cancellation is the first proposed disposition; generic blocked-to-READY retry is explicitly excluded.

## Implementation order and acceptance evidence

1. Implement/test reviewed ownership descriptors and a pure bounded collector against real migrated disposable SQLite. An explicitly constrained empty-effect first slice must reject every unsupported relationship; never call it general complete inventory.
2. Add immutable observation schema with additive populated-upgrade tests, FK/uniqueness/immutable-update/delete constraints and rollback/idempotency tests. No existing phase or execution state change is needed for a private observation.
3. Add canonicalization/hash/freshness tests, then actual independent-handle collection races and whole-package integration/vet; add hosted Linux race and native Windows selectors. Only wire maintenance/public inspection once privacy, fairness and bounded work are established.

## Indirect structural prerequisite implemented — 25 October 2026

`ValidateIndirectOwnershipSchema` now checks the bounded main-schema structural
boundary for21reviewed indirect tables and existing direct-table anchors. The
embedded contract includes normalized table DDL to bind CHECK/default/unique
definitions as well as columns, keys and FKs. It detects new/changed relevant
Worker/Operation/Event/artifact/Library/recovery/delivery references and respects
main-schema isolation, UTF-8 byte budgets and read-only observation. Actual
migrated-SQLite positive/negative evidence is in the execution manifest. Tests
validate reviewed source without rewriting the contract during execution.

This does not close steps1–4 above. Standalone indexes/triggers, typed Worker
step/reference discriminators, row vocabularies, polymorphic dependencies,
dual Event delivery pointers, ambiguous request encodings and durable bounded
attribution still need their separate semantic protocols. The descriptor text
documents those paths; it is not executable attribution. No observation
collector, immutable snapshot/decision schema, independent postcondition proof
or recovery authority is enabled by structural success.
