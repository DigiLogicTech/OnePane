# RC11 P0-AA — Offline paired Node custody countersignature

This increment introduces a narrow explicit local Go API to countersign a human-verified one-shot instrument report using the enrolled Node federation Ed25519 identity. It establishes two independently enrolled **signing keys** bound to the same original report and human approved source/target/plan. It does **not** establish two independently trustworthy sensors.

The original instrument receipt is first checked against the independently retained human OnePane challenge, private approved exact TCP plan and enrolled instrument public key. A Node may then create one time-bounded (at most 60 seconds after observed time and before nonce expiry) versioned envelope containing SHA-256 digests of the original private receipt and challenge plus Project/Goal/key/nonce/target/TLS pin/source/outcome/times. The private IPv4 and port stay out of the envelope; treat their digests as sensitive metadata.

Independent verification requires exact original receipt, challenge, approved plan, enrolled instrument public key, and independently pinned Node certificate DER and fingerprint. Checks include both signatures, certificate subject and client-auth EKU, digital signature usage, certificate validity at historical witness time, exact canonical envelope, observation chronology and fingerprint equality.

**Safety constraints:** No HTTP API, no federation transmission, no background sender, no socket, no Task, no instrument key export, no autonomous incident voting, no sensor device-health upgrade, no same-physical-device correlation and no remediation is introduced. The Node merely countersigns an operator-supplied self-report using a software-held TLS identity key. It does not prove the Node ran the instrument, that a physical endpoint was really probed, independent network vantage, trusted wall clock or TPM/TEE attestation. A dishonest key holder or a compromised operator input channel can still fabricate evidence. All operator files must be independently obtained and protected.

Further work must add a human-governed Node-local execution path and appropriate physical provenance, exact same-target review and incident policy, reversible recovery with rollback, low-resource soak and code/security audit. Perform comprehensive human-centred UI/UX alignment LAST before explicitly approved installers and installed physical QA.
